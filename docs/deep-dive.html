team6 · technical deep-dive

How the growing-agent harness actually works.

The engineering under the pitch: one contract, a reward-gated loop, a self-curating memory, and inference-time levers — all domain-agnostic, off-by-default, and offline-capable. .NET 8, Azure AI Foundry.

01 · the shape

Three layers. One contract. Any domain.

The whole system is a small BCL-only core plus two thin layers. An agent implements three methods — nothing else changes per agent; the loop, memory, and tools are written once.

agent (3 methods)→ AgentHarness· ILessonStore· ToolLoop→ AgentHost (HTTP) 
interface IAgent {
  // build a draft; injected lessons up front, prior draft + critique on revisions
  Task<string> GenerateAsync(ctx, lessons, critique, priorDraft, attempt, ct);
  // the reward — deterministic, unhackable, reproducible
  Reward Evaluate(string draft, AgentContext ctx);
  // mint the lesson for a mistake the loop just fixed
  Lesson? LessonFor(string trigger, AgentContext ctx);
}

Swap Evaluate and the same harness grows a value-investing agent, a code agent (reward = unit tests), or a UI-from-design agent (reward = design tokens). Proven across four domains.

02 · the fast loop

Improve within a run and run-to-run.

for iter in 0..MaxIters:
  best-of-N: draw Samples drafts, evaluate each, keep the reward's winner   // inference-time compute
  if passed and no critic objection: break
  critique = reward.Critique (+ optional LLM/vision critic notes)          // revise, don't restart
if still below threshold and escalate is set:
  one attempt on a STRONGER model — kept only if the reward scores it higher  // hard cases only
write-back: record each injected lesson's hit-rate
learn: for every attempt-1 mistake the loop FIXED → mint a lesson → store
  • Within a run: best-of-N + revise-on-critique + self-verify lift the draft.
  • Run-to-run: a fixed mistake becomes a lesson; the next run retrieves it. The pipeline compounds.
  • Invariant: the reward is the sole authority for scoring and selection. Critics and escalation only add revision signal or a fallback attempt — they never override the reward.
03 · the reward

One function, triple duty — and it's the training target.

record Reward(
  bool Pass,                       // hard gates
  double Score,                    // graded 0..1 — drives best-of-N selection
  IReadOnlyDictionary Breakdown,   // components (for transparency)
  IReadOnlySet FailedTriggers,     // which rules failed → drives learning + hit-rate
  string Critique);                // an actionable fix-list for the next revision

It must be deterministic and unhackable — an environment check, not another LLM opinion. That is what makes the loop trustworthy and what a future ART/GRPO trainer optimizes verbatim.

04 · memory

Semantic recall, and a memory that curates itself.

A lesson is {agent | sector | trigger} → warning text, an embedding, trust, and hit-rate stats. Retrieval is a four-step pipeline behind the ILessonStore seam:

filter: agent · sector · not-quarantined→ embed situation → cosine shortlist→ LLM recall: which APPLY?→ two-phase load top-K

Self-curation — a memory that only appends, rots

  • Trust: learned lessons start Provisional → promote to Verified on hit-rate or a human gate. Injection-suspicious lessons are Quarantined and never injected.
  • Decay + eviction: stale/low-hit lessons drop in ranking and are evicted over a per-agent cap.
  • Conflict: re-learning the same trigger with opposing guidance (cosine < 0.6) demotes the rule and resets its stats — it must re-earn trust. An optional LLM check flags cross-lesson contradictions.
  • Dedup: near-duplicates (cosine ≥ 0.92) merge instead of piling up.

Same three ops (Retrieve/Write/RecordApplication), swappable backing: a local JSON file, or Cosmos DB with server-side vector search (DiskANN over the embedding, partition /agent). Verified by memlife/ (decay/eviction/conflict) & abeval/ (retrieval holds while exact-match collapses).

05 · the amplifier

Inference-time compute — a weak model, lifted.

Four levers, each a clean seam, each off by default and inert without a live model, so the offline pipeline is byte-for-byte unchanged.

Best-of-NHarnessOptions.Samplesthe reward keeps the best of N independent drafts
Web-search groundingWebSearchTool in ToolLooplook facts up instead of hallucinating
Self-verifyICritic (LlmCritic / VisionCritic)catch soft errors the deterministic reward can't

Injected as optional constructor deps on AgentHarness; the host turns them on from env (AGENT_SAMPLES, AGENT_SELF_VERIFY, AGENT_LLM_MODEL_STRONG). No IAgent change.

06 · tools & grounding

Facts, memory, MCP, and pixels.

Tool loop

OpenAI function-calling with a safety partition: read-only tools run free; mutating/outward tools must pass a permit gate.

Real MCP

McpToolSource is a stdio JSON-RPC client — initialize → tools/list, each wrapped as a gated ITool. 13 tools discovered live.

Vision

CompleteVisionAsync grounds UI generation in a design image, and powers a vision critic that compares output to the target.

UI-from-design: three tiers of grounding

  • Tier 1 — image: generate from the Figma screenshot (multimodal), not a text description.
  • Tier 2 — vision critique: the model compares its output to the target and iterates on the visual/behavioural diffs (clickable stars, disabled Save), learning them.
  • Tier 3 — exact tokens: ground on get_design_context — the design system's real values (#6f42c1, Poppins, the gradient). The harness reaches for the precise tool, the way web_search grounds a fact.
07 · cost

Metered tokens, and the escalation lever.

Every completion records its usage to a CostLedger, so a run's cost is a real number — not an estimate. The cost-optimization win is escalation: run mini+harness, and the reward escalates to the frontier model only on the tasks it can't crack.

// measured vs gpt-5.1, 15 hard reasoning traps (escbench)
always gpt-5.1          10/15   $0.01362   premium on 15/15
cheap-first + escalate  10/15   $0.00975   premium on  6/15  → ~72% of frontier cost

The reward is the escalation gate — a deterministic "does this need the frontier model?" signal. Same quality (even gpt-5.1 solves only 10/15), a fraction of the cost, on a model you control.

08 · the flywheel

Every run is training data — for free.

The loop keeps every (draft, reward) in HarnessOutcome.Attempts; TrainingExporter turns a run into three trainer-ready shapes:

  • SFT — the winning completion as the target (imitation).
  • Preference / DPO — best vs a lower-scored attempt (reward-model data).
  • RL / GRPO — every attempt tagged with its scalar reward (policy-gradient data).

We don't need ART to ship — the fast loop already grows the agent. But the moment a GPU appears, the dataset already exists. That's "ART-ready" made concrete (flywheel/).

09 · why not ART directly

The fast loop is the Foundry-only rung.

ART (OpenPipe's Agent Reinforcement Trainer) makes a model better by changing its weights — it needs GPU compute, open weights, a training backend, and gradient access. A hosted Foundry model gives you none of those. Our pattern optimizes the same reward without touching weights: it improves the context (retrieved lessons + revision), live, on a plain inference endpoint. ART is the optional slow loop — a later, GPU-bound upgrade that reuses the exact reward and the flywheel's data. Not a dependency.
