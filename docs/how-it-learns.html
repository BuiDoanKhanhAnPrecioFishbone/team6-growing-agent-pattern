for developers how an agent gets better

The agent learns from its own reward-verified mistakes — and from your experts.

No fine-tuning, no GPU. A mistake the loop fixes becomes a lesson the next run recalls; every run is also training data for later. Here's exactly how — and what you write.

01 the core idea

A fixed mistake becomes a lesson. The next run recalls it.

generate→ reward.Evaluate→ FailedTriggers→ revise & fix→ LessonFor(trigger) → store
next run→ retrieve relevant lessons→ inject into the prompt→ avoids the mistake — first try

The whole thing is context engineering driven by a reward: the reward says what "wrong" means, the fix becomes a durable note, and retrieval brings the right note back at the right moment.

02 a lesson's life · a real example

Born from a failed trigger; applied by retrieval.

// RUN 1 — the agent cites a source it wasn't given
Evaluate(draft) → Reward{ Pass:false, FailedTriggers:["UNCITED_SOURCE"], Critique:"cite only provided sources" }
loop revises → fixes it → the harness calls:
LessonFor("UNCITED_SOURCE") → Lesson{
  Id: "s2-moat|consumer_staples|UNCITED_SOURCE",   // {agent|sector|trigger} = upsert key
  Warning: "Cite only the provided sources; never invent a citation.",
  Embedding: [ … ],  Trust: Provisional }  → store.WriteAsync

// RUN 2 — same sector, new company
RetrieveAsync(agent, situation) → [that lesson] → injected up front → the agent cites correctly, first try.

You never write retrieval or prompt-plumbing — you write Evaluate (what failed) and LessonFor (the note). The harness stores, ranks, injects, and tracks whether it helped.

03 the lesson & how it's retrieved

A tiny record, retrieved by meaning.

class Lesson {
  string Id;              // "{agent}|{sector}|{trigger}" — upsert key
  string Warning;         // the guidance injected next time
  float[] Embedding;      // vector of (condition + warning) — for semantic recall
  Trust  Trust;           // Provisional | Verified | Quarantined
  int    TimesApplied, TimesHelped;  double HitRate;  // self-correction stats
}

Retrieval is a 4-step pipeline — never dump the whole memory into the prompt:

filter: agent · sector→ embed situation → cosine shortlist→ cheap LLM: which APPLY?→ inject top-K

04 trust & curation

A memory that only appends, rots. This one curates itself.

Provisionala freshly learned lesson — used, but on probation
Verifiedearned it: hit-rate ≥ 0.6 & helped ≥ 2×, or a human confirmed it
Quarantinedinjection-suspicious — stored, but never injected
  • Decay + eviction: stale, low-hit lessons drop in ranking and are evicted over a per-agent cap.
  • Conflict: re-learning the same trigger with opposing guidance demotes the rule and resets its stats — it must re-earn trust.
  • Dedup: near-duplicates (cosine ≥ 0.92) merge instead of piling up.
  • Hit-rate: every injected lesson is scored on whether it prevented its own mistake — a lesson that stops helping decays out.

05 humans teach, too

Your experts correct the agent in plain language.

A reviewer rejects an output and states the rule. It's stored as a Verified lesson immediately (a human said so), and the agent applies it on the next run — knowledge work compounds.

// the /api/teach flow, live in the UI
human: "Always end an investment note with the not-advice disclaimer."
  → store.WriteAsync(Lesson{ Warning: …, Trust: Verified, LearnedFrom: "human reviewer" })
  → every future note includes it.

Same memory, two sources of learning: the reward (automatic) and people (explicit). Both become durable, ranked, curated lessons.

06 every run is training data

The fast loop ships today; the same runs make you train-ready.

The loop keeps every (draft, reward) in HarnessOutcome.Attempts. TrainingExporter turns a run into three trainer-ready shapes — for free:

SFT imitation

{messages:[user, assistant=winning draft]} — the passing completion as the target.

Preference DPO

{prompt, chosen, rejected} — best vs a lower-scored attempt.

RL GRPO / ART

{prompt, completion, reward} — every attempt tagged with its scalar reward.

fast loop— same reward —→ slow loop (ART: weights, GPU, later)

We don't need ART to ship — the fast loop already grows the agent, live, on a plain Foundry endpoint. But the day a GPU appears, the dataset already exists. No rework.

07 the approach · what YOU write

Three methods. The harness does the rest.

class MyAgent : IAgent {
  // 1) produce a draft — injected lessons + prior critique arrive as parameters
  Task<string> GenerateAsync(ctx, lessons, critique, prior, attempt, ct);
  // 2) the REWARD — deterministic; its FailedTriggers drive learning
  Reward Evaluate(string draft, ctx);
  // 3) mint the lesson for a trigger the loop just fixed
  Lesson? LessonFor(string trigger, ctx);
}
  • You own: the reward (what "better" means) and the lesson text.
  • The harness owns: retrieval, injection, best-of-N, revise, trust, decay, eviction, conflict, the data export — written once, never per agent.
