Agentic Financial Statement Analyzer

The Compounding
Analyst

We don't ship prompts. We ship a harness — and grow analysts inside it whose edge compounds run over run.

Pattern: agent-as-policy in a deterministic environment · Learning: two speeds, one reward · Memory: a knowledge graph that remembers

Investing is too large to one-shot. So each analysis step is an agent living in a deterministic financial environment it cannot fabricate — with tools to act, a knowledge-graph memory of every company, thesis, and lesson, and one reward that gates it today and trains it tomorrow. The agent grows. The cost goes down.

§1 — The engine

Two-speed learning over a single reward

The core engineering claim: the same self-evaluation function is the inference-time gate and the training signal. Both loops optimize the same thing — so every run you serve is also data that makes the next one better.

One reward
reward(output, environment)  →  gate now  AND  training signal later

▸ Fast loop

every run · Foundry-only · cheap
generate→ evaluate→ reflect→ retrieve lesson→ revise→ pick best→ write lesson

Improves within a run and run-to-run via graph memory. No GPU, no weight updates — pure Azure Foundry.

▸ Slow loop

offline · optional · GPU
pooled high-score traces→ ART · GRPO→ better base policy→ redeploy to Foundry

Bakes memory into weights. ART is an upgrade, not a dependency — the graph is already the dataset.

quality ↑ while cost ↓ — the agent gets smarter and cheaper over time
§2 — The substrate

One harness contract, six agents

Uniformity is the flex: every step implements the same interface, so the six agents are one composable, testable shape — not six scripts.

Agent — harness contracttypescript
Agent = {
  id,  consumes[],  produces,        // reads & appends one block of the candidate file
  environment,                       // deterministic core it narrates over — SOURCE OF TRUTH, never trained
  tools[],                           // deterministic ops + graph queries (the agent does NOT do math)
  reward(output, environment),       // self-eval → { score, gatesPassed, critique }  ← gate = training signal
  memory: {
     retrieve(features) -> Lesson[], // scoped top-k lessons from the KG, ranked by hitRate
     write(lesson)                   // episodic write-back after evaluation
  },
  gate?: humanConfirm,               // optional typed interrupt (human-in-the-loop)
  growth: "reflect" | "reflect+train" // fast loop always; slow loop only where it pays
}

§4 — The memory

A knowledge graph that remembers

The candidate file is a materialized view of one company's subgraph. Every number links to a provenance node; lessons live in the graph and are retrieved to inform whoever writes the next block.

Company Statement · Metric Provenance Thesis Evaluation Lesson · hitRate Run
schema — nodes & edgesgraph
(Company {ticker, name, sector, exchange})
  ├─[:HAS_FINANCIALS]→ (Statement {period, type})
  │                      └─[:HAS_METRIC]→ (Metric {name, value, unit})
  │                                         └─[:SOURCED_FROM]→ (Provenance {source, stmt, period, url})
  ├─[:HAS_THESIS]→ (Thesis {id, claim, asOf, stage:S1..S6, humanConfirmed})
  │                  └─[:EVALUATED_BY]→ (Evaluation {agent, scoreA, outcomeB?, gatesPassed, date})
  │                                        └─[:PRODUCED]→ (Lesson)
  └─(Run {id, agent, iterations, bestScore, model, cost}) ─[:FOR]→ (Thesis)

(Lesson {id, agent, warning,
        sector, deMin, deMax, triggers[],          // the CONDITION — fires only when relevant
        date, timesApplied, timesHelped, hitRate})  // self-correcting stats
   └─[:APPLIED_IN {helped:bool}]→ (Run)
scoreA — process quality

Grounded, complete, no hallucinated figures. Immediate. Drives learning now. Teaches analytical discipline.

outcomeB — did it play out

Price / earnings vs thesis. Laggy, noisy. Recorded for later. Never let it masquerade as scoreA.

memory.retrieve — fast-loopcypher
MATCH (l:Lesson)
WHERE l.agent = $agent
  AND l.sector = $sector
  AND $de >= l.deMin AND $de <= l.deMax
  AND any(f IN $redFlags WHERE f IN l.triggers)
RETURN l ORDER BY l.hitRate DESC, l.date DESC
LIMIT 5     // retrieval budget: never dump the whole memory
write-back — self-correctioncypher
// after a run where lesson L was injected; $improved = did scoreA beat baseline?
MATCH (l:Lesson {id:$id})
SET l.timesApplied = l.timesApplied + 1,
    l.timesHelped  = l.timesHelped  + (CASE WHEN $improved THEN 1 ELSE 0 END),
    l.hitRate      = toFloat(l.timesHelped) / l.timesApplied
// lessons that decay below a floor stop being retrieved → the graph prunes its own bad notes
§5 — The economics

Cost-optimized by construction

The scope is one LLM from Azure AI Foundry. So thrift isn't a feature bolted on — it's enforced by the harness, and it improves as the graph fills.

Environment does math
Zero tokens per calculation — the calculators, not the LLM.
Model cascade
Small Foundry model by default; escalate only when reward fails a gate.
Retrieval budget
Top-5 lessons, never the whole memory. Prompt can't bloat.
Prompt cache
Stable environment context repeats across iterations & companies.
Capped + stop-at-target
K bounded; halt on target score. No runaway reflection.
Distill down
Slow loop trains a small model → steady-state inference gets cheaper.
Steady state — as the graph fills
